TASK 2 — THE OPTIMIZER (4 POINTS)
Three transformations of the checked tree behind --optimize, run before code generation:
• Unused variables (1 point) — a declaration nobody reads is removed with its assignments, again and again until
a pass removes nothing; scopes and shadowing are respected; an expression that calls a function or read() is
never dropped.
• Unused functions (1 point) — a function nobody calls is removed with its whole body, again and again:
removing a body may leave another function unused.
• Inlining (2 points) — a function called exactly once is replaced at its call site by its body: each parameter becomes
a local declaration initialised with the argument, the exit of the body becomes the value that stands where
the call stood, names are renamed so they cannot collide with the caller’s, and the function is then removed as
unused. A recursive function is never inlined. The README says which shapes you inline and which you leave
alone, for example a body that leaves through exit inside an if.
The proof is mechanical. A folder of at least 6 programs, two per transformation, each with the expected tree after
--optimize --ast and the expected output; the output is the same with and without the flag. Every other test
of your suite also passes with the flag. Add to the README one before/after excerpt of the IR for the inlining of
one function.TASK 3 — THE REAL PROGRAM (4 POINTS)
A program in your language that a person can use: it prints prompts, reads input, computes something and prints
results. It uses at least one structure with a member function, at least one function, read and print, and your
feature — visibly, not in a corner. What it does is up to you: a small game, a calculator over structures, a filter over
values, a scheduler of tasks if you built threads or coroutines.

3. What I took as it was, what I changed, and why

I did not write the code of this stage by hand. The assistant wrote it and I
decided what was built. "Changed" below means a change from the assistant's first
version, with the reason. The first group of decisions is mine; the fixes were
found by running the program and the tests, and the assistant made them.

Decisions that were mine:
- The feature. The assistant recommended Loops with break as the lowest risk. I
  did not take that recommendation and chose the most impressive feature instead,
  which is higher-order functions.
- The branch: stage3 created from stage2, as I asked in message 2.
- The aims in message 1: full test coverage, separate commits, and a disclosure
  that fixes the -0.5 from my earlier ai_usage.txt.

Task 1, higher-order functions (lexer.py, parser.py, ast_nodes.py, grammar.ebnf,
semantics.py, codegen.py):
- Taken as it was: the design and the code. That covers the function type, the
  lambda syntax, capture by value, the pair of a body pointer and a heap
  environment, thunks for named serves, and the rule that a local function
  variable hides a serve but a non-function variable does not.
- Changed: the module now sets the host target triple, because llc refused the
  old "unknown-unknown-unknown". The lambda token stayed a kaomoji and not a word,
  because a new reserved word would break Stage 2 programs that use that name.

Task 2, the optimizer (optimizer.py, compiler.py):
- Taken as it was: the three passes, the InlinedCall and ExpressionStatement nodes,
  the renaming to function.N.name, and rechecking the tree after every pass.
- Changed: the command line now uses parse_intermixed_args, because the first
  version failed on "input --optimize output" and the task says the flag works
  anywhere. An unused card whose initializer has a call now keeps only those calls,
  because keeping the initializer itself made the recheck fail. Arithmetic that may
  overflow is kept, because removing it would remove an abort and change the output;
  the task only names calls and read(), so this is stricter than it asks.

Task 3, the program (programs/):
- Taken as it was: the idea of Function Forge, the code and the prompts.
- Changed: undo now restores the stage count, because the first recorded session
  showed the wrong count after an undo. The labels of the square stage and of the
  empty recipe were reworded after reading the output.
- The two recorded sessions were generated by running the program. The assistant
  checked the values by hand before they were recorded.

Tests (tests/):
- Taken as it was: all new programs, the optimizer folder and the changes to
  tests/run_tests.py. Expected trees and outputs were recorded from the compiler

- Changed: the unused_variables_effects test first aborted on overflow by mistake.
